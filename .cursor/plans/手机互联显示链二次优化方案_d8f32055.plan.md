# 手机互联显示链二次优化方案

## 目标

- 把当前 [runcarplay/src/carplay_display/carplay_display.c](/home/hyby/Desktop/myShare/v853s_sample-new/v853s_sample-new/runcarplay/src/carplay_display/carplay_display.c) 的“`VDEC_SendStream -> GetImage -> VO_SendFrame`”路径，改成你确认可用的 `VDEC -> VO` 绑定路径。
- 彻底解决日志中的 `VideoRenderEventHandler` / `VideoRenderEmptyBufferDone` 报错，核心是补齐 **非空 MPP callback**。
- 对 `wait vbs data timeout` 做保守处理：先避免把它放大成逻辑抖动或额外切换，不以“完全消灭 SDK 内部告警”作为首轮目标。

## 现状结论

- 当前实现仍然是手动取帧送显，不是直绑：见 [carplay_display.c](/home/hyby/Desktop/myShare/v853s_sample-new/v853s_sample-new/runcarplay/src/carplay_display/carplay_display.c) 中的 `AW_MPI_VDEC_GetImage()` 与 `AW_MPI_VO_SendFrame()`。
- 当前唯一 bind 是 `CLOCK -> VO`，不是 `VDEC -> VO`。
- 第二版日志里大量报错的直接原因，是 VO 事件路径要求 callback 非空：
  - [log/第二版运行日志.log](/home/hyby/Desktop/myShare/v853s_sample-new/v853s_sample-new/log/第二版运行日志.log) 中反复出现 `VideoRenderEmptyBufferDone Error! User should RegisterCallback to mpp!`
  - MPP 宏检查在 [mm_common.h](/home/hyby/Desktop/myShare/v853s_sample-new/v853s_sample-new/external/aw_pack_src/lib_aw/include/eyesee-mpp/middleware/include/media/mm_common.h) 中明确要求 `MPPCallbackInfo.callback != NULL`
- 现有参考实现已经在 [runcarplay/src/app/video/mpp_camera.c](/home/hyby/Desktop/myShare/v853s_sample-new/v853s_sample-new/runcarplay/src/app/video/mpp_camera.c) 里演示了 `AW_MPI_VO_RegisterCallback()` + `MPPCallbackWrapper` 的基本写法。
